# Atomicity Policy

An atomic checklist item has one primary action, one source plan operation, one observable expected result, explicit completion evidence, and at least one mapped verification item. Atomicity is semantic rather than merely textual: joining unrelated edits with “and” is prohibited even if represented as one sentence.

A checklist item may touch multiple files only when those files are inseparable mechanical manifestations of the same approved operation. Any new business rule, fallback, transaction boundary, concurrency policy, public contract, migration strategy, or security decision requires loopback.
